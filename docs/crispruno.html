처음1. 인덱스 만들기2. CRISPRuno

CRISPRuno 0.1.22(clementlab)의 분석을 브라우저에서 단계별로 실행합니다: prep → UMI → primer/adapter trimming → minibwa 정렬 → read 할당 → CRISPResso 정량 → 요약·리포트. bowtie2 대신 minibwa로 정렬하고, Cas-OFFinder 검색은 빠져 있습니다. 파일은 브라우저 저장소(OPFS)의 run 폴더에 원본과 같은 이름으로 남습니다.

환경

실행 중인 worker 없음

1. Run과 settings

CRISPRuno settings 파일 형식(줄마다 key<TAB>value, # 주석)을 그대로 씁니다. 명령줄 옵션도 같은 형식의 줄로 적으면 됩니다(예: keep_intermediate True). 파일 경로는 이름만 봅니다 — fastq_r1/fastq_r2/fastq_umi/cut_region_annotation_file은 아래에서 고른 파일 중에서 찾습니다. genome/aligner_genome은 무시하고 아래에서 고른 인덱스·FASTA를 씁니다.

웹 전용 옵션
bowtie2 --very-sensitive-local 대신. -b MD는 자동으로 붙습니다(MD 태그로 양끝 일치 길이를 봄). primer를 잘라낸 짧은 read(30 bp~)도 정렬되도록 최소 점수를 낮추고(-s 20 -m 20), read 끝의 mismatch를 bowtie2 local처럼 soft-clip하도록 끝 보너스를 낮춘 값(--end-bonus=5, minibwa 기본 10; 이 앱의 minibwa에 추가한 옵션)이 기본입니다.
bowtie2 --end-to-end -c 대신 primer와 guide 서열을 read로 정렬합니다(20 bp도 정렬되도록).

2. 입력 파일

origin 서열, homology 검색(±30 bp), CRISPResso amplicon에 쓰입니다(samtools faidx 대신). .fai를 함께 고르면 색인 시간을 줄입니다. 비워 두면 인덱스의 .l2b에서 읽습니다(IUPAC 문자는 N).

3. 실행

단계원본 (CRISPRunoCore.py)상태

각 단계는 앞 단계가 run 폴더에 남긴 파일을 읽습니다(원본의 재사용 파일과 같은 방식). 한 단계만 다시 돌릴 수도 있습니다. 정렬기가 minibwa라 read 위치·MAPQ가 bowtie2와 조금 다를 수 있고, 같은 정렬(SAM)이 들어가면 나머지 단계의 출력 파일은 원본과 같도록 이식했습니다.
